Публикации содержат прямую ссылку на товар внутри сообщения с включённым предпросмотром Telegram; ссылка на обсуждение не выводится.
Бот извлекает ссылки из полного RSS-содержимого, раскрывает известные переходы агрегаторов
и при необходимости проверяет кнопку покупки на странице предложения. Адрес товара не
угадывается по названию. Если получить ссылку не удалось (например, HTTP 403), предложение
остаётся в очереди до следующего запуска, пока не устареет. Для рыночного сравнения, купонов и экстремальных скидок карточка магазина проверяется отдельно.

Поддерживаемые магазины перечислены в `store_links.py` (`MERCHANTS`). Amazon принимается
только с идентификатором ASIN, Newegg — с путём товара `/p/` или параметром `Item`.

### Прямые магазины и производители

Кроме агрегаторов бот самостоятельно читает публичные каталоги Amazon, Newegg,
Corsair (RAM, БП, охлаждение, мыши, клавиатуры, гарнитуры), MSI, Samsung, Crucial,
ASUS и Google Store. Источники с `type="store"` включены по умолчанию; их ID
перечислены в `sources.py`. Отключение — через `DISABLE_SOURCES`, как и для RSS.

Цены берутся из карточек товаров, JSON-LD и данных каталога магазина. Варианты с
неоднозначной ценой, другой валютой, отсутствием на складе или предзаказом
пропускаются. Для Corsair дополнительно проверяются наличие и цены конкретного SKU
в `__NEXT_DATA__`. Обычная цена магазина обозначается как MSRP, а не выдаётся за
подтверждённую историческую цену. Если магазин не сообщает исходную цену, бот
накапливает собственную историю этого товара в этом магазине и ждёт подтверждения
скидки по прежним правилам. Дата обхода каталога не является датой публикации акции.

Каталоги опрашиваются раз в 15 минут, недоступные магазины — раз в 30 минут.
HTTP 403/503, CAPTCHA и отсутствие читаемых цен видны как ошибки источника; обход
блокировок не выполняется. При проверке из текущей среды Amazon, Newegg и MSI
блокировали запросы, а Google Store не отдавал однозначные цены Pixel в HTML.
Наличие адаптера не гарантирует доступность магазина с IP GitHub Actions.

Комплектующие, периферия и Google Pixel публикуются перед ноутбуками/готовыми ПК.
Добавлены категория микрофонов, категория Pixel и поисковые RSS-запросы по Pixel,
мышам, клавиатурам, гарнитурам и микрофонам. Цены Pixel с trade-in, активацией тарифа
или ежемесячными платежами не считаются обычной ценой покупки.

Новых Python-зависимостей нет: непрерывный workflow может подхватить изменения через
имеющийся `sync_code`. Новые значения Variables/Secrets запущенный job автоматически
не перечитывает, но для включённых по умолчанию прямых источников это не требуется.

### Синхронизация непрерывного запуска

`workflow_git.py` сохраняет `data/` отдельным коммитом поверх свежей удалённой ветки
через временный Git index. Rebase для сохранения состояния не используется.
При обновлении кода локальные данные сначала копируются за пределы checkout,
незавершённая Git-операция отменяется, затем данные восстанавливаются поверх
обновлённого checkout. Этот helper разрешено запускать только в GitHub Actions.

Если состояние не удалось отправить за шесть попыток или JSON повреждён, цикл
останавливается; `data/` сохраняется как Actions artifact на 7 дней. Следующий
запуск по цепочке разрешён после успешного завершения либо сохранения аварийного artifact; восстановление ограничено двумя попытками.
Изменения самого workflow требуют нового запуска: текущий shell-скрипт цикла
не перечитывается при `sync_code`.

### Ссылки и фото в публикациях

Если в ленте или точной карточке есть изображение товара, бот вызывает `sendPhoto`: фото и подпись с прямой ссылкой «Открыть товар в магазине», без кнопок. Если подпись длиннее лимита Telegram, она сокращается с сохранением ссылки. Если изображения нет либо Telegram явно отклонил URL изображения, отправляется `sendMessage` с предпросмотром прямой ссылки. В логах отдельно видно подтверждение фото, отправку текста и причину отклонения картинки. Таймаут с неизвестным результатом не запускает немедленный текстовый дубль. `last_delivery` в checkpoint содержит тип последней подтверждённой отправки и message_id. Уже отправленные сообщения не изменяются.

В поиск по умолчанию включены `drum machine`, `sampler`, `synthesizer`, `Roland AIRA`. Музыкальное оборудование распознаётся как `music_gear` раньше компьютерных клавиатур; стандартный порог скидки — 20% и $30, переопределение: `RULES_JSON`. Поисковые источники активны без изменения `ENABLE_SOURCES`, кроме явно отключённых через `DISABLE_SOURCES`.

### Сравнение цен между магазинами

Если собственной истории ещё нет и обычные правила не подтверждают скидку, бот пробует сравнить предложение с **двумя другими независимыми магазинами**. За базу берётся самая низкая из подтверждённых цен, а к цене предложения прибавляется известная доставка. Пороги категории из `RULES_JSON` сохраняются. Например, $500 против $750 и $800 может пройти проверку уже при первом наблюдении.

Сопоставление строгое: проверенный GTIN или бренд + MPN производителя. Для Google Pixel допускается полное совпадение поколения, Pro/XL/Fold, памяти, цвета и явно указанного unlocked; противоречащие GTIN/MPN исключаются. Автоматическое сравнение применяется к новым товарам с обычной ценой, без trade-in, тарифа и членства. Общедоступный купон допускается после проверки итоговой цены на точной карточке магазина. Наличие, USD и продавец должны подтверждаться страницей магазина. Для маркетплейсов принимаются только явно указанные Amazon, Newegg и другие поддержанные собственные продавцы площадок. Неизвестная доставка текущего предложения блокирует этот способ подтверждения. Налоги по адресу покупателя не рассчитываются.

Цены из RSS-заголовков, MSRP и поисковых сниппетов не являются рыночными доказательствами. Бот использует структурированные данные прямых каталогов и перепроверяет точные товарные ссылки, найденные в подключённых источниках. Известные ссылки хранятся до 30 дней (до 2000), подтверждённые цены — 15 минут (до 1000). На цикл допускается до 12 проверок карточек и до 4 поисковых запросов; новые запросы перестают начинаться после общего бюджета 60 секунд; неудачные проверки повторяются не чаще раза в 10 минут. Сплошного поиска по всему интернету нет: точные ссылки дополнительно ищутся по артикулу, как описано ниже. Amazon/Newegg с блокировкой HTTP 403/503 остаются недоступными для подтверждения; обход защиты и платный сервис не подключены.

В публикации указываются минимальная цена других магазинов, экономия и ссылки на подтверждения. Ссылка внутри сообщения ведёт на проверенное предложение. Подходящие, но неподтверждённые предложения сохраняются для повторной автоматической оценки, пока не истечёт `MAX_DEAL_AGE_HOURS` (без молчаливого удаления хвоста очереди). Раздел отчёта «Не опубликованы — причины автоматической проверки» объясняет недостающие данные; ручного одобрения он не требует.

### Защита непрерывного цикла

Перед заменой checkout `workflow_git.py sync` компилирует все Python-файлы удалённого коммита. При синтаксической ошибке обновление отклоняется, локальное состояние сохраняется, run завершается с ошибкой. Перед каждым проходом также проверяется синтаксис. Один проход ограничен 10 минутами (затем TERM и через 30 секунд KILL); после трёх подряд неуспешных проходов цикл завершается и освобождает очередь. Успешный проход сбрасывает счётчик. Safety net сохраняет `data/`, а при сбое создаётся artifact.

Один ожидающий запуск при работающем цикле допустим: `concurrency` запрещает параллельных издателей, чтобы не дублировать сообщения. Изменения оболочки workflow вступают в силу в новом запуске.

### Восстановление после ошибки сохранения

Git-команды ограничены 120 секундами. Состояние отправляется до 6 раз с паузами 2/4/8/16/32 секунды; ответ Git выводится с удалением URL и токенов. При исчерпании попыток публикации прекращаются, `data/` сохраняется в artifact. Перед следующим боевым запуском скачивается последняя резервная копия этой ветки, если она новее последнего коммита `data/state.json`; оба JSON-файла проверяются до замены данных. Повреждённая или неполная копия останавливает запуск до публикаций.

Цепочка использует встроенный `GITHUB_TOKEN` с `actions: write`, отдельный `DISPATCH_PAT` больше не нужен. После ошибки следующий запуск разрешён при успешном сохранении artifact; ошибка первоначального восстановления также допускает повтор до публикаций, максимум два восстановления подряд. После успешного цикла счётчик сбрасывается. Отменённые пользователем, smoke и dry-run запуски цепочку не запускают. Cron остаётся резервным механизмом, время его доставки GitHub не гарантирует. Сообщение сравнения `0/2` означает недостаток цен конкурентов и не является ошибкой процесса.

### Поиск точного товара для сравнения

`market_search.py` ищет карточки по MPN производителя или корректному GTIN. Для Pixel допускается полный вариант: поколение/Pro/XL/Fold, память, цвет, unlocked. Если артикул отсутствует в ленте, бот сначала пытается получить его с прямой страницы магазина. Произвольные цифры из заголовков артикулом не считаются.

Прямой поиск выполняется на Amazon, Newegg, B&H и Best Buy; для Corsair используется официальный поиск каталога. Для других поддержанных производителей используется поиск Bing RSS с ограничением на официальный домен. Поисковик может не вернуть подходящих результатов. Из поисковой выдачи берутся только ссылки, соответствующие идентификатору, без цен и MSRP. Затем каждая карточка проходит отдельную проверку цены, наличия, продавца и версии товара. Совпадение названий без точных идентификаторов для комплектующих не подходит. Производитель считается одним независимым магазином, а сайт самого предложения не считается конкурентом.

Максимум на цикл — 4 поисковых запроса и 12 проверок карточек, общий бюджет 60 секунд; один поиск ограничен 20 секундами. Поиск одного товара повторяется не чаще раза в 2 минуты. Сначала проверяются ещё не проверявшиеся товары, затем самые давно проверенные; внутри равного приоритета ускоряются экстремальные скидки. Один запрос на товар за проход, поисковые площадки чередуются. Слоты распределяются по производителям: сначала один товар от каждого, между проходами приоритет получает давно не обслуженный бренд. Внутри бренда сохраняется очередь ещё не проверенных и давно проверенных товаров. Из бюджета списываются фактические запросы. Очередь ограничивается этими лимитами, найденные ссылки сохраняются для последующей перепроверки. При отказе в логах видны конкретные домены и причины: HTTP 403, проверка браузера, отсутствие точных ссылок или исчерпание квоты. Блокировки магазинов не обходятся, платных API и новых секретов нет. Условие двух других подтверждённых магазинов и пороги скидки остаются прежними; отсутствие данных не заменяется на MSRP.


### Атомарное состояние и очередь предложений

`data/checkpoint.json` — единственный источник истины: `generation_id`, `saved_at`, `state` и `history` записываются одним атомарным `replace` с `fsync`. Предыдущее поколение хранится в `checkpoint.backup.json`. `state.json` и `history.json` остаются совместимыми экспортами; оборванный экспорт не подменяет корректный checkpoint. Старый формат мигрирует автоматически при первом сохранении. `null`, неверные типы и повреждённая история вызывают восстановление резервного поколения или остановку, а не обнуление базы.

Весь хвост `pending` сохраняется до первой отправки. Состояния доставки: `queued → processing → sending → delivered`, окончательные ошибки — `failed_permanently`. Недостаток подтверждений сохраняет запись; экстремальная скидка получает `priority_verification`. Временные ошибки Telegram оставляют `attempts`, `reason`, `retry_at`; HTTP 429 учитывает полный `retry_after`. Если неизвестно, принял ли Telegram запрос, запись получает `delivery_unknown` и повторяется позже. Telegram не предоставляет ключ идемпотентности для `sendMessage`: в таком случае повтор сообщения возможен, гарантировать exactly-once нельзя.

Свежая цена вытесняет старую запись той же карточки; старое наблюдение не перезаписывает свежую котировку. Изменение цены принудительно обходит кэш карточки. `assessment_cache` хранит причину, статус, ревизию важных полей, `rules_version` и `parser_version`; отказ не блокирует последующую переоценку. `processed` сохранён для совместимости и аудита отправок, но не служит вечным запретом. Повторы контролирует TTL `posted`; наблюдаемый рост и последующее падение цены образуют новое событие даже внутри окна.

Купоны разбираются по ролям: `$100 with $20 coupon` и `$100 with $20 off coupon` дают $80, `$80 after coupon` остаётся $80. Неоднозначные суммы сохраняются для уточнения карточки. Купон не удаляет MPN/GTIN; без подтверждённой общедоступности и итоговой суммы предложение остаётся в очереди. Скидка выше 85% ускоряет проверку и сама по себе не считается фейком. Противоречивые цены вариантов каталога сохраняются с неизвестной ценой для перепроверки, а не выбираются по минимуму.

При конкурентном Git-сохранении объединяются подтверждённые отправки, свежие pending/котировки и история цен. Новые записи удалённого состояния не заменяются целиком локальным файлом. Карточки магазинов поддерживают максимум три HTTPS-редиректа только между разрешёнными доменами. Добавлены товарные ссылки Sweetwater, Guitar Center, Musician’s Friend, zZounds, American Musical и Perfect Circuit. Сбор источников выполняется в отдельных процессах: зависший источник принудительно завершается по общему или индивидуальному сроку.

Локальная проверка: `python -m pip install -r requirements-dev.txt`, затем `python -m pytest -q`. Матрица регрессий аудита: [AUDIT_ACCEPTANCE.md](AUDIT_ACCEPTANCE.md).


В отчёте примеры ожидающих предложений чередуются по источникам (до 15 строк из всей очереди), а локальная пауза опроса каталога показывается как «пауза опроса до … Ташкент». HTTP 304 означает только реальный ответ ленты, а не отсутствие сетевого запроса во время паузы.


В подписи Telegram отображается «⚖️ Вес: … кг». Вес берётся из Product.weight / additionalProperty JSON-LD либо явно подписанных характеристик Item/Product/Net Weight на точной странице товара. Граммы, фунты и унции переводятся в килограммы. Вес упаковки/доставки, диапазоны и числа без единиц не используются. Если вес не указан, сообщение содержит «Вес: не указан»; публикация не блокируется. Фото и вес извлекаются одним запросом карточки перед отправкой.
